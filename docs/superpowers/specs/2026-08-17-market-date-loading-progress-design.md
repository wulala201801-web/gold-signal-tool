# 黄金红绿灯行情日期与加载进度设计

## 目标

修复页面顶部日期写死为 `2026.8.13` 的问题，并为行情更新增加符合现有纸张仪表风格的可视化进度。更新过程必须清楚、克制，不改变评分公式或行情数据接口。

## 行情日期

- 删除 CSS 伪元素中写死的日期。
- 在标题栏增加真实日期元素，由 JavaScript 写入。
- 成功取得完整 payload 后，使用 `payload.fetchedAt` 生成 `YYYY.M.D` 日期。
- 页面使用完整缓存时，继续显示该缓存 payload 的 `fetchedAt` 日期，不能显示设备当天日期并伪装成最新行情。
- 数据尚未取得且没有完整缓存时，日期显示 `数据待更新`。

## 黄铜刻度条

进度组件位于标题日期栏下方、红黄绿主灯上方。视觉使用暖金色、黄铜边框、纸张底色和轻微内阴影，与现有页面一致。

组件包含：

- 横向进度槽与填充条。
- 进度百分比。
- 当前阶段文案。
- 自动重试时的连接次数。

页面加载后立即显示进度组件。成功完成后显示 `100% · 数据更新完成`，保留约一秒后收起，不长期占用主视觉空间。

## 进度逻辑

后端当前一次性返回完整评分，没有逐数据源流式进度。因此百分比是基于等待时间的加载表现，不声称代表已经完成的数据源数量。

- 8%–35%：`正在连接行情`。
- 35%–70%：`正在获取市场数据`。
- 70%–92%：`正在校验并计算灯号`。
- 接口未完成前最高停留在 92%。
- 完整 payload 返回并通过校验后跳至 100%。

进度更新使用平滑过渡。请求较快时允许直接跨越中间阶段，不能为了动画故意延迟数据显示。

## 缓存与重试

- 有完整缓存时，页面先保留缓存灯号和分数，同时显示更新进度。
- 实时更新失败时继续显示缓存结果，并把进度状态改为 `连接失败，准备重试`。
- 自动重试沿用现有 5 秒、15 秒、30 秒策略。
- 每次自动重试显示 `重新连接 · 第 N 次`，进度回到 12% 后重新推进。
- 三次自动重试均失败后停止动画，显示明确错误；刷新按钮恢复可用。
- 没有完整缓存时，主灯号保持未知状态，进度组件仍负责呈现连接和重试状态。

## 响应式规则

- 电脑端进度条横跨标题区域下方。
- 手机端保持单行进度槽，阶段文案与百分比分列两端。
- 不增加横向滚动，不改变现有交通灯、评分卡、行情卡和行动建议的顺序。

## 验收标准

1. 页面不再包含写死的 `2026.8.13`，顶部日期与完整 payload 的 `fetchedAt` 一致。
2. 缓存数据明确显示缓存对应日期，不能误显示设备当天日期。
3. 首次加载和手动刷新均显示黄铜刻度条、阶段文案和百分比。
4. 未收到完整评分前进度不超过 92%；完整评分通过校验后才显示 100%。
5. 有缓存时更新过程不清空当前灯号和分数。
6. 自动重试时显示连接次数，最终失败后动画停止且错误可读。
7. 数据快速返回时不人为延迟灯号更新。
8. 桌面与手机布局均无溢出，现有评分公式与接口字段保持不变。
9. JavaScript 语法、现有自动恢复测试、新增日期和进度状态测试以及 `git diff --check` 全部通过。
