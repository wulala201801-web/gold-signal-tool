# 黄金红绿灯行情连接稳定性设计

## 目标

解决页面偶发显示“无法连接”的问题。在行情源短暂波动、Vercel 冷启动或用户网络不稳定时，页面应优先显示可追溯的最近一次完整评分，而不是清空主灯号。

## 根因

- 前端请求每次附加随机 `fresh` 参数，导致 Vercel 无法复用后端设置的五分钟共享缓存。
- 后端顺序请求六组行情，线上实测一次完整请求约 13 秒，延迟和失败概率随数据源数量累积。
- 页面只把完整结果保存到单台设备的 `localStorage`。首次访问或旧缓存被清除后，单次接口失败就没有可展示的兜底结果。

## 设计

### 1. 恢复服务端共享缓存

前端固定请求 `/api/market`，使用默认 HTTP 缓存语义，不再添加随机查询参数。后端只对完整评分返回：

`Cache-Control: public, s-maxage=300, stale-while-revalidate=600`

同一五分钟内的访问可直接复用完整结果。手动点击“刷新数据”只重新读取当前可用的完整服务端结果，不承诺绕过保护性缓存。

### 2. 后端并行获取行情

使用固定六个工作线程并行获取黄金、美元指数、美元兑日圆、纳斯达克、VIX 和实际收益率。评分公式、数据来源和各数据源超时时间不变。

并行任务完成后仍按原有字段写入 `data` 和 `errors`，避免前端协议变化。目标是将完整接口响应从约 13 秒降低到最慢单个数据源所需时间附近。

### 3. 保留最近一次完整评分

设备端只保存完整 payload。实时请求失败时：

- 有完整本地缓存：显示最近一次完整评分、原始行情时间和“缓存数据”提示。
- 没有完整本地缓存：保留“无法连接”，同时显示具体错误类型，允许用户再次刷新。
- 任何不完整 payload 均不能覆盖完整缓存，也不能生成灯号。

本次不引入数据库、定时任务或新的第三方服务。跨设备共享的历史快照不在本次范围内。

## 错误呈现

前端区分三类状态：HTTP 接口错误、响应内容不完整、浏览器网络失败。用户界面使用简短中文提示，详细错误仅作为状态辅助信息，不改变评分。

## 验证

1. 本地测试确认六组行情并行执行，评分字段与现有结构一致。
2. 连续请求线上 API 三次，均返回 HTTP 200 和完整的 `macroRisk`、`priceHeatRisk`、`combinedRisk`、`signal`。
3. 第二次请求应命中共享缓存或明显快于首次冷请求。
4. 模拟接口失败时，已有完整缓存仍显示灯号、分数和缓存时间。
5. 模拟首次访问且接口失败时，页面显示可辨识的失败原因，不使用不完整评分。
6. JavaScript、Python 语法检查和 `git diff --check` 全部通过。
